# Archived books and restoration verification — 2026-11-23

Implemented the approved librarian-only Archived books view within Manage books. Existing active catalog services remain active-only. Dedicated archived reads authorize first, use escaped literal title/author search and the shared twelve-row pagination owner, and show protected covers, archive dates and derived active/archived copy counts. An archived review provides explicit confirmation, warns if no copies are active, and uses a native POST with CSRF. Search, selection, close and page links retain archived context. Active and archived tabs reuse existing account-tabs styling and native navigation motion; the accepted pagination design is unchanged.

Restoration rechecks fresh actor/session under the existing actor→book lock order. It compares the displayed archive timestamp AND latest catalog.archive_book audit ID (0 for legacy records), so stale forms cannot restore a later archive even within the same second. It clears only books.archived_at and writes catalog.unarchive_book atomically. A repeated POST is rejected without another mutation or audit. Author credits, physical copies and borrowing history are retained. Individually archived copies are never restored by this action; existing catalog availability remains derived. Administrators can read the audit event but cannot view archived titles/covers or restore them. No database schema migration is required.

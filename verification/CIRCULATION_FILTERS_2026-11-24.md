# Circulation sorting and status-filter verification — 2026-11-24

Implemented the approved controls within the existing three librarian queues. Review requests sort by oldest/newest submission and shortest/longest requested borrowing period, default oldest. Pickups filter All outstanding, Ready and Expired and order by nearest/farthest collection deadline, default nearest. Returns filter All outstanding, Overdue, Due today and Active-not-overdue and sort by earliest/latest due date, default earliest. Active includes loans due today. These defaults preserve existing ordering and surface the oldest/most urgent work first.

Shared app/circulation_filters.php validates every key; views/circulation_filters.php renders native labelled GET controls. Services append only fixed allowlisted ORDER BY/predicates, parameterize search and apply filters before count/limit. Deterministic request IDs break ties. Existing callers remain compatible through a trailing optional options array. Search, selection, page counts, pagination links, validation errors and successful action redirects preserve the URL context. Applying controls omits page and starts at1; Clear restores defaults. Native forms/mutations, CSRF and role checks are unchanged. Expired allocations cannot be physically handed over; return confirmation remains required.

Expiry is the existing exact48-hour UTC boundary. Overdue compares the stored due date against the current Philippine calendar date; due-today equality remains non-overdue through the full day. Cancelled/collected/returned records stay outside these outstanding queues; this is not a historical-expiry browser. No persisted status, schema migration, policy or pilot-record mutation is introduced. Due-today labels and queue status/deadline summaries improve scanning without changing full record details or actions. Existing themes, navigation animation and pagination design remain.
